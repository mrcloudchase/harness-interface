Every coding agent, one API, sandboxed.

Harness Gateway runs coding-agent CLIs, the harnesses, one turn at a time in sandboxes it owns, and exposes them through the OpenAI Responses API. Bring your providers and your harness packages. The platform runs the turn, relays the provider calls through a gateway that holds the keys, and keeps the complete record.

What it does

Bring your providers

Anthropic, OpenAI, DeepSeek, anything with the same shapes. The key is sealed on arrival and decrypted only inside the gateway, for one upstream call at a time. It never enters a sandbox.

Bring your harness packages

A folder: how to install the CLI, how to run one turn, what to return. Fork one of twenty-two verified packages from the catalog, or upload your own. The platform never reads what the scripts print.

Ask through the Responses API

Any OpenAI SDK works unchanged. model names a harness. Continue a session with previous_response_id, stream the output, steer or cancel a running turn.

Sandboxed by construction

A fresh container per turn, no capabilities, a read-only root, the tenant's own uid and ceilings, and a door that tunnels only to the hosts the package names and refuses private addresses.

The complete record

Every request, steer, cancel and response in the trace; every provider exchange captured; the workspace snapshotted after each turn and downloadable.

Hosted or yours

One image, four roles, one compose file. Records in SQLite or Postgres, blobs in a directory or any S3 store, no cloud SDK anywhere else. The same code is harnessgateway.ai and your own box.

First request

curl -s https://harnessgateway.ai/v1/responses -H "Authorization: Bearer $KEY" -H 'content-type: application/json' \
  -d '{"model": "claude-code", "input": "Create hello.txt containing the word hello, then reply with the one word: done"}'
